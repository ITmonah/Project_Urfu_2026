# Model cards моделей определения заполненности КГО

Данные для обучения моделей были поулчены от заказчика. Разметка проводилась на платформе CVAT

## MC-01: YOLO-детектор площадки

### 1. Model Details — сведения о модели

- Тип: детекция объектов, Ultralytics YOLO; рабочий артефакт — `Yolo26s_kgo.pt`, общий для трёх Web/API-режимов.
- Имя файла предполагает вариант YOLO26s, но архитектура этого checkpoint не подтверждена. В [training-ноутбуке](../datasetCreation/yolo_finetune.ipynb) явно используется **YOLO26n**, исходные веса `yolo26n.pt`, результат `weights/best.pt`.
- Вход: фотография; выход: bounding boxes, классы и confidence. Прикладные пайплайны ищут имя `kgo_platform`, а не фиксированный числовой class ID.
- Код интеграции: [NCD](../NewClassificatorNoDino/pipeline.py), [SAM](../SAM_model/pipeline.py), [SMP](../SMP_model/pipeline.py). Разработчик базы — Ultralytics, дообучение — команда проекта; прочие метаданные см. общие сведения.

### 2. Intended Use — назначение

Найти границы площадки КГО и подготовить область для оценки заполненности. Пользователи — ML-сервис, разработчик и ответственный сотрудник. Самостоятельное определение физического объёма отходов, работа с произвольными объектами и полный учёт всех площадок на фото не являются подтверждёнными применениями.

### 3. Factors — факторы качества

Особенно важны маленькие и перекрытые площадки, несколько площадок в кадре, нестандартные ограждения и смещение камеры. Отдельной оценки таких случаев нет. NCD выбирает первый подходящий box, SAM/SMP — наиболее уверенный, поэтому различия детекции влияют на итоговые сравнения подходов.

### 4. Metrics — метрики и пороги

mAP@50, mAP@50:95, precision/recall по классам, прежде всего recall `kgo_platform`. Проект не задаёт явно `conf`/`iou` для рабочего инференса и использует настройки установленной версии Ultralytics. Эти пороги не следует путать с порогами заполненности сегментаторов.

### 5. Evaluation Data — данные оценки

В сохранённом YOLO26n-эксперименте — 7485 изображений и 15772 объекта суммарно. Конфигурация задаёт `train: images` и `val: images`: **оценка проводится на тех же изображениях, что и обучение**. Независимой тестовой оценки рабочего `Yolo26s_kgo.pt` нет. Состав train/val нужно исправить до выводов об обобщающей способности.

### 6. Training Data — обучение

Ноутбук объединяет пять ZIP-экспортов YOLO; список имён в YAML: `garbage_can`, `kgo_empty`, `kgo_full`, `kgo_platform`. Конфигурация YOLO26n: 50 эпох, `imgsz=320`, batch 32, patience 8, seed 42, `pretrained=True`, `optimizer="auto"`, `amp=False`. Исходные архивы в репозитории отсутствуют. Параметры дообучения рабочего файла с именем YOLO26s неизвестны.

### 7. Quantitative Analyses — результаты

Финальный сохранённый вывод `model.val` для YOLO26n: mAP@50 **0.9853**, mAP@50:95 **0.7126**, precision **0.9637**, recall **0.6195** по всем оцениваемым классам. Для `kgo_platform` в выводе округлено: precision **0.946**, recall **0.938**, mAP@50 **0.984**, mAP@50:95 **0.744**. Это результаты на обучающих изображениях; они не характеризуют независимый test и не приписываются рабочему checkpoint. End-to-end показатели трёх цепочек см. [MC-07](#mc-07-система-из-трёх-пайплайнов).

### 8. Ethical Considerations — этические аспекты

Пропуск площадки может задержать проверку и вывоз; ложное обнаружение приводит к ошибочной оценке посторонней области. Фото могут содержать людей, номера машин и адресные сведения: для датасета следует ограничивать лишние персональные данные и доступ к исходным снимкам.

### 9. Caveats and Recommendations — ограничения

Подтвердить архитектуру рабочих весов, зафиксировать class map и хеш. Проверять правильность отображения ID классов при объединении архивов: пересортировка имён сама по себе не перенумеровывает аннотации. В SMP при отсутствии имени `kgo_platform` используются все детекции — такой checkpoint нужно считать несовместимым для выпуска. Отсутствие box не означает пустую площадку.

## MC-02: EfficientNetV2-S для кропа

### 1. Model Details — сведения о модели

Бинарный классификатор Torchvision `efficientnet_v2_s`; артефакт `best_efficientnet_v2_s_kgo.pth`. Рабочая загрузка ожидает `state_dict` и `class_names`; архитектура создаётся с `weights=None`, затем загружается прикладной checkpoint. Вход — RGB-кроп первого YOLO-box: `Resize(256)` с сохранением соотношения сторон, `CenterCrop(224)`, тензор, ImageNet-нормализация (mean `[0.485, 0.456, 0.406]`, std `[0.229, 0.224, 0.225]`). Код: [NCD pipeline](../NewClassificatorNoDino/pipeline.py). Роль файла устанавливается конфигурацией, а не его именем.

### 2. Intended Use — назначение

Определить `kgo_empty` / `kgo_full` по области площадки. Выход нужен для поддержки проверки сотрудником. Классификатор не вычисляет процент и не умеет сам находить площадку или распознавать её отсутствие.

### 3. Factors — факторы качества

Ошибки YOLO, неточный кроп и потеря краевых объектов при центральном обрезании. Значимы дисбаланс состояний и критерий разметки «заполнено». Оценки по типам площадок нет.

### 4. Metrics — метрики и пороги

Accuracy, macro F1, recall `kgo_full`, ROC-AUC для бинарных score. Класс выбирается через argmax; максимальная softmax-оценка сравнивается с оценкой классификатора полного фото. При равенстве выбирается кроп. Порог отказа по низкой уверенности и калибровка моделей не реализованы.

### 5. Evaluation Data — данные оценки

Есть экспериментальный бинарный EfficientNetV2-S на 643 test-кропах (397 `kgo_empty`, 246 `kgo_full`), но не доказано, что это именно рабочие веса. Перечень площадок и независимость test относительно серий съёмки неизвестны. Оценка полного NCD-пайплайна на 235 фото приведена отдельно в MC-07.

### 6. Training Data — обучение

[prepare_datumaro_dataset.py](../datasetCreation/prepare_datumaro_dataset.py) создаёт кропы `kgo_platform` с метками состояния. [train_classifiers.py](../datasetCreation/train_classifiers.py) использует ImageNet1K V1, два класса, stratified split 70/15/15, seed 42; по умолчанию 30 эпох, batch 16, AdamW, lr `1e-4`, weight decay `1e-5`, CrossEntropyLoss, ReduceLROnPlateau, early stopping 4. Эти настройки описывают доступный training-путь, а не подтверждённое происхождение рабочего checkpoint.

### 7. Quantitative Analyses — результаты

Эксперимент в [train_classifiers.ipynb](../datasetCreation/train_classifiers.ipynb): accuracy **0.909798**, macro F1 **0.906255**, ROC-AUC **0.974693**, recall `kgo_full` **0.9350**. Это изолированный экспериментальный классификатор; показатели рабочего ансамбля из MC-07 нельзя переносить на него.

### 8. Ethical Considerations — этические аспекты

Ложное `kgo_empty` может оставить заполненную площадку без внимания; ложное `kgo_full` приводит к лишней проверке. Решение о вывозе должно учитывать фото и контекст. Требования к приватности исходных снимков совпадают с MC-01.

### 9. Caveats and Recommendations — ограничения

Training-путь масштабирует кроп сразу в `224×224`, рабочий инференс использует resize + center crop; преобразования нужно согласовать. Разделять исходные фото/площадки до нарезки кропов, чтобы кропы одной фотографии не попадали одновременно в train и test. Проверять порядок `class_names`; значения checkpoint в этой работе не прочитаны.

## MC-03: EfficientNetV2-S для полного фото

### 1. Model Details — сведения о модели

Torchvision EfficientNetV2-S на три предполагаемых класса: `kgo_empty`, `kgo_full`, `kgo_none`. Артефакт — `best_efficientnet_for_full.pth`, формат `state_dict` + `class_names`; фактический порядок задаёт checkpoint. Вход — полное RGB-фото, `Resize(256)` → `CenterCrop(224)` → ImageNet-нормализация. Код: [NCD pipeline](../NewClassificatorNoDino/pipeline.py), [train_classifier.py](../NewClassificatorNoDino/train_classifier.py).

### 2. Intended Use — назначение

Уточнить результат классификатора кропа с учётом более широкой сцены. Модель вызывается только после успешной YOLO-детекции; она не заменяет детектор для фотографий, на которых YOLO ничего не нашёл. `kgo_none` обозначает отсутствие результата.

### 3. Factors — факторы качества

Фоновая обстановка, размещение площадки вне центра, размер целевого объекта и ошибочное формирование класса `kgo_none`. Срезы качества не исследованы.

### 4. Metrics — метрики и пороги

Для отдельной модели: macro F1, per-class precision/recall, confusion matrix на три класса; ROC-AUC требует multiclass one-vs-rest/one-vs-one и вероятностей всех классов. Рабочий выбор — argmax и сравнение максимальных softmax-оценок с кроп-моделью. В training-скрипте бинарный вызов AUC использует только `all_probs[:, 1]` и перехватывает исключение: он не даёт корректный трёхклассовый AUC. Баллы двух моделей не откалиброваны.

### 5. Evaluation Data — данные оценки

Training-скрипт задаёт stratified split 70/15/15, seed 42. Размеры выборок и отдельные результаты рабочего полного классификатора отсутствуют. Снимок оценки на 235 фото относится к совместному NCD-пайплайну, см. MC-07.

### 6. Training Data — обучение

[prepareDataset.py](../NewClassificatorNoDino/prepareDataset.py) сохраняет полные фото из Datumaro в три класса; фото без метки состояния автоматически получает `kgo_none`, что требует проверки разметки. Training-вход `classification_data`; 50 эпох максимум, batch 32, AdamW lr `1e-4`, weight decay `1e-5`, patience 10, CrossEntropyLoss, ImageNet1K V1; обучающие аугментации включают RandomResizedCrop, отражение, поворот и ColorJitter. Связь результата скрипта с `best_efficientnet_for_full.pth` не зафиксирована.

### 7. Quantitative Analyses — результаты

Изолированные измерения **не предоставлены**. В полном пайплайне с этой моделью заявлены accuracy **0.9404** и macro F1 **0.9534** на 235 фото; эти числа характеризуют всю цепочку, включая YOLO, кроп-классификатор и правило выбора ответа. Вклад полного классификатора требует ablation-сравнения с той же цепочкой без него.

### 8. Ethical Considerations — этические аспекты

Связь метки с фоном вместо состояния площадки может ухудшить работу на новых территориях. Ошибочный `kgo_none` скрывает необходимую проверку. Требования к персональным данным см. MC-01.

### 9. Caveats and Recommendations — ограничения

Валидация training-скрипта использует растяжение до `224×224`, инференс — center crop; необходимо единообразие. Сохранять проверенные примеры всех трёх классов, отдельно оценивать `kgo_none` и калибровку. API выводит общую подпись «no kgo_platform» и для `kgo_none`, поэтому по ответу нельзя однозначно установить, какой компонент отказался.

## MC-04: SAM ViT-B с семантическим декодером

### 1. Model Details — сведения о модели

`SAMSemanticMulticlass`: image encoder Segment Anything ViT-B и собственный свёрточный декодер на четыре класса: 0 — фон, 1 — пол, 2 — стена, 3 — мусор. Используется энкодер исходной модели Meta, а не стандартная prompt-сегментация SAM. Артефакт `sam_model.pth` содержит state dict всей прикладной модели. Код: [pipeline.py](../SAM_model/pipeline.py), [training-ноутбук](../SAM_model/train_model.ipynb).

Вход — RGB-кроп с отступом 8%, LongestMaxSize до 1024 и padding до `1024×1024`, ImageNet-нормализация. TTA усредняет логиты оригинала, горизонтального/вертикального отражения и поворота на 90°. Выход — карта четырёх классов, маска мусора и метка заполненности.

### 2. Intended Use — назначение

Выделить видимые части площадки и мусора, получить визуальную оценку заполненности и объясняющую маску. Не измеряет массу, объём и скрытые отходы; не распознаёт опасные виды мусора.

### 3. Factors — факторы качества

Малый объём масок, перекрытие пола мусором, перспектива, цвет покрытия и различия между training-изображениями и YOLO-кропами. Морфологическая очистка влияет на мелкие предметы. Срезы качества не опубликованы.

### 4. Metrics — метрики и пороги

IoU/Dice по классам, mIoU, pixel accuracy и качество итоговой метки. Рабочая формула: `min(100, 100 × A_мусор / (A_пол + A_стена))`; `kgo_full` при **≥ 70%**. Маска очищается морфологическим закрытием и фильтрацией компонентов с минимальной площадью `max(1, A_площадка × 0.0005)`. Доля не является процентом физической вместимости.

### 5. Evaluation Data — данные оценки

Сохранённый эксперимент: **21** validation-изображение с масками; независимый test не показан. `compute_metrics` исключает пиксели с истинной меткой фон перед расчётом: ошибки на реальном фоне не входят в эти показатели. SAM и SMP используют разные методики mIoU; напрямую ранжировать их по этим notebook-числам нельзя.

### 6. Training Data — обучение

В выводе — **168** training-изображений. Инициализация `sam_vit_b_01ec64.pth`; декодер обучается поверх замороженного энкодера. Конфигурация: до 100 эпох, `1024×1024`, batch 2, AdamW lr `1e-4`, CosineAnnealingLR, AMP, CrossEntropyLoss с весами классов и `ignore_index=0`; лучший checkpoint выбирается по validation mIoU. Ноутбук содержит ветку попытки разморозки блоков с номерами ≥ 24 после 40-й эпохи; её фактический эффект следует проверить для используемого ViT-B. Training resize и рабочий resize + padding различаются.

### 7. Quantitative Analyses — результаты

Финальная validation-оценка лучшего `best_model.pth` в ноутбуке: pixel accuracy **0.9045**, mIoU **0.7760**; IoU/Dice пола **0.7853 / 0.8797**, стены **0.8766 / 0.9342**, мусора **0.6661 / 0.7996**. Не доказано, что `best_model.pth` идентичен рабочему `sam_model.pth`. End-to-end снимок на 235 фото: accuracy **0.8000**, macro F1 **0.6320**, 5 ответов без зоны (см. MC-07); он оценивает цепочку YOLO → SAM → порог, а не только маски.

### 8. Ethical Considerations — этические аспекты

Убедительная цветная маска может создавать излишнее доверие к неверной оценке. Результат нужно проверять по исходному фото; пустой/некачественный результат не должен автоматически подтверждать уборку. Приватность снимков см. MC-01.

### 9. Caveats and Recommendations — ограничения

Мусор не входит в знаменатель формулы, значение ограничивается 100%; оно несопоставимо с процентом SMP. При нулевой площади пола/стены возвращается `0%` и `kgo_empty`, даже если это ошибка сегментации. В inference маска после padding растягивается до исходного размера кропа без явного удаления padding; геометрию и расчёт площадей следует проверить. Протокол оценки должен включать фон, отказы и независимый test, а также совпадать с preprocessing/TTA рабочего режима.

## MC-05: DeepLabV3+ с энкодером SE-ResNeXt50

### 1. Model Details — сведения о модели

Segmentation Models PyTorch `DeepLabV3Plus`, encoder `se_resnext50_32x4d`, 3 входных канала, 4 выходных класса: фон/пол/стена/мусор. Артефакт `best_model_SMP.pth`, ключ `model_state_dict`. Код: [pipeline.py](../SMP_model/pipeline.py), [training-ноутбук](../SMP_model/train_model.ipynb). Вход — YOLO-кроп в RGB, resize `512×512`, ImageNet-нормализация; выход — argmax-карта классов. TTA в рабочем SMP не применяется.

### 2. Intended Use — назначение

Сегментировать область площадки, оценить видимую долю мусора и сформировать метку. Предназначен для поддержки проверки сотрудником; измерение реального объёма, заполненности скрытой области и оценка отдельных видов отходов не подтверждены.

### 3. Factors — факторы качества

Качество масок, неточность YOLO-кропа, растяжение сторон до квадрата, перекрытия и перенос на новые площадки. Часть сопоставлений меток подготовки масок (`kgo_empty`, `kgo_full`, `kgo_platform` → мусор) зависит от исходного экспорта и требует проверки. Срезов качества нет.

### 4. Metrics — метрики и пороги

IoU/Dice мусора, mIoU и итоговые classification-метрики. Формула по умолчанию: `A_мусор / (A_пол + A_стена + A_мусор)`; `kgo_full` при доле **≥ 0.5**. В Web/API передаётся доля × 100. При нулевом знаменателе возвращается 0. Исследовательский `use_floor_only=True` меняет знаменатель и требует отдельной настройки; Web/API его не использует.

### 5. Evaluation Data — данные оценки

В notebook-выводе **42** validation-изображения, случайный split 80/20 с seed 42; независимого test нет. mIoU рассчитывается без класса фон, затем усредняется по batch с весом размера batch, а не из общей confusion matrix всего датасета. Это отличается от SAM-протокола и должно быть указано при сравнении.

### 6. Training Data — обучение

В notebook-выводе **168** training-изображений и масок. Encoder инициализируется ImageNet-весами; 70 эпох максимум, batch 4, lr `1e-4`, AdamW weight decay `1e-4`, loss `0.5 × DiceLoss + 0.5 × CrossEntropyLoss`, ReduceLROnPlateau patience 5, early stopping 15. Лучший checkpoint выбирается по validation loss. [dataset_creation.py](../SMP_model/dataset_creation.py) имеет split **100/0/0** и структуру `dataset/train/images`, тогда как notebook ожидает `dataset/images`: это отдельные несогласованные этапы подготовки, не готовый воспроизводимый training-workflow.

### 7. Quantitative Analyses — результаты

В журнале обучения последняя лучшая модель сохранена на эпохе **48**: validation loss **0.2479**, validation IoU **0.6284** по описанной batch-методике. Это не test-оценка; соответствие сохранённого `best_model.pth` рабочему `best_model_SMP.pth` не подтверждено. End-to-end снимок на 235 фото: accuracy **0.8681**, macro F1 **0.8298**, 5 ответов без зоны (MC-07).

### 8. Ethical Considerations — этические аспекты

Ошибка границ зоны меняет процент и может изменить решение о вывозе. Следует учитывать стоимость ложного отрицательного и ложного положительного решения и предоставлять ручную проверку. Приватность фото см. MC-01.

### 9. Caveats and Recommendations — ограничения

При нулевой зоне нужна отдельная обработка неопределённости, а не подтверждение пустоты. Проверить соответствие цветовых масок и индексов 0–3. Для независимого сравнения сегментаторов использовать один протокол IoU/Dice и один end-to-end датасет; threshold 50% — параметр текущего кода, не доказанный оптимум для заказчика.

## MC-06: экспериментальные классификаторы кропов

### 1. Model Details — сведения о модели

Семейство бинарных моделей для сравнения архитектур, не зарегистрированное в трёх Web/API-режимах. [classifier_models.py](../pipeline/classifier_models.py) создаёт **ResNet18, ResNet34, ResNet50, EfficientNetV2-S и ConvNeXt-Tiny**, заменяя классификационную голову на два класса. Для нового training-пути используются ImageNet1K V1; старый ResNet50-ноутбук использует V2. Каждый вариант — отдельная модель с собственным checkpoint и результатами в таблице ниже. Вход — RGB-кроп `224×224`, выход — `kgo_empty` / `kgo_full`.

В [train_classifiers.py](../datasetCreation/train_classifiers.py) также есть ветка YOLOv8n-cls (`yolov8n-cls.pt`). Её запуск в сохранённом notebook заканчивается ошибкой, подтверждённых метрик нет. Она не загружается общим Torchvision-loader и не является рабочим режимом приложения.

### 2. Intended Use — назначение

Сравнение классификаторов, выбор кандидата и исследовательский CLI [predict_image.py](../predict_image.py). Нельзя считать все обучаемые варианты моделями, используемыми Web/API, или победу на кропах доказательством лучшего качества полного сервиса.

### 3. Factors — факторы качества

См. MC-02: ошибка кропа, ракурс, фон и освещение. Сравнение проводится при одинаковых split, но группировка по исходным фотографиям/площадкам не реализована. Нет анализа срезов или неопределённости результатов.

### 4. Metrics — метрики и пороги

Accuracy, macro precision/recall/F1, weighted F1, balanced accuracy, binary ROC-AUC и average precision. Класс выбирается argmax; новый training-путь выбирает checkpoint по validation macro F1, при равенстве — по loss. Полные per-class показатели сохранены в ноутбуке.

### 5. Evaluation Data — данные оценки

В [train_classifiers.ipynb](../datasetCreation/train_classifiers.ipynb): **4285** кропов, split **2999 / 643 / 643**; test содержит 397 пустых и 246 заполненных. Эти результаты относятся к кропам, созданным по аннотациям, а не к ошибочным детекциям YOLO. Старый [resnetTrain.ipynb](../datasetCreation/resnetTrain.ipynb) использует отдельные **2172** кропа со split **1520 / 325 / 327**, на test 143 пустых и 184 заполненных; сравнивать числа между этими двумя экспериментами напрямую нельзя.

### 6. Training Data — обучение

Новый путь: AdamW lr `1e-4`, weight decay `1e-5`, CrossEntropyLoss, максимум 30 эпох, batch 16, seed 42, stratified split, scheduler ReduceLROnPlateau, patience 4. Старый ResNet50: ImageNet V2, AdamW lr `5e-5`, batch 32, 30 эпох; random_split без зафиксированной в этой ячейке группировки. Исходные данные отсутствуют, обучающие split не воспроизведены.

### 7. Quantitative Analyses — результаты

Сохранённая test-таблица нового эксперимента (643 кропа):

| Модель | Accuracy | Macro F1 | ROC-AUC | Recall `kgo_full` |
| --- | ---: | ---: | ---: | ---: |
| ResNet18 | 0.903577 | 0.898992 | 0.961838 | 0.9024 |
| ResNet34 | 0.897356 | 0.893716 | 0.969144 | 0.9309 |
| ResNet50 | 0.895801 | 0.891501 | 0.961889 | 0.9106 |
| EfficientNetV2-S | 0.909798 | 0.906255 | 0.974693 | 0.9350 |
| ConvNeXt-Tiny | 0.925350 | 0.922117 | 0.980863 | 0.9431 |

В этом эксперименте ConvNeXt-Tiny имеет наибольшие accuracy и macro F1. Старый ResNet50 на другом test из 327 кропов: accuracy **0.9419**, macro F1 **0.9413**, ROC-AUC **0.9927**, recall `kgo_full` **0.9239**. Это не свидетельство превосходства над новым сравнением, поскольку датасет иной. Числа приведены из сохранённых outputs, не из повторного обучения.

### 8. Ethical Considerations — этические аспекты

Выбор по одной общей метрике может скрывать пропуски заполненных площадок и слабые условия съёмки. Проверять per-class recall и разнообразие площадок до использования кандидата в бизнес-процессе. Приватность фото см. MC-01.

### 9. Caveats and Recommendations — ограничения

В старом ResNet50-ноутбуке все `Subset` используют один dataset: присваивание transform через `val_ds.dataset`/`test_ds.dataset` меняет transform также для train. Новый training-путь нужно предпочесть после проверки разделения исходных фото. CLI по умолчанию использует ConvNeXt-Tiny, но не загружает его веса автоматически. Для ResNet18/34 нужен явный `--classifier-checkpoint`; выбор `yolo` в CLI не даёт совместимый Torchvision-checkpoint. Для рабочего ансамбля нужно проверить preprocessing и изолировать вклад каждой модели.

## MC-07: система из трёх пайплайнов

### 1. Model Details — сведения о системе

Составная ML-система FastAPI с режимами `new_classifier_nodino`, `sam`, `smp`; компоненты см. MC-01–MC-05. [Маршрутизатор инференса](../fastapi_app/inference.py) нормализует ответы. NCD выбран по умолчанию в коде. Источник чисел — [снимок таблицы, предоставленный пользователем](evaluation/pipeline-metrics-provided.png); дата запуска оценки и версии весов не сообщены.

### 2. Intended Use — назначение

Оценка заполненности площадок по фото сотрудников для поддержки проверки и решения о вывозе в проекте для СБЕР. Пользователи — сотрудник, ответственный за вывоз и ML-команда. Применение к оценке труда сотрудников, автономному планированию маршрутов и измерению вместимости не подтверждено.

### 3. Factors — факторы качества

Все факторы отдельных компонентов, качество запроса, частота отсутствия детекции и правило объединения моделей. Оценка по сезонам, площадкам, освещению и камерам в предоставленной таблице отсутствует.

### 4. Metrics — метрики и пороги

Accuracy, macro precision/recall/F1, weighted F1, `No Zone`, `Errors`. Рабочие decision thresholds описаны в README. В [текущем скрипте оценки](../scripts/evaluate_metrics.py) macro-метрики считаются по двум истинным классам, ответы `no_zone` дают false negatives; accuracy учитывает все оцениваемые фото. Errors входят в число `no_zone` при исключении инференса. Формат снимка совпадает с отчётом скрипта, но наличие исходного CSV/JSON и версия вычисления не подтверждены. В таблице нет ROC-AUC, recall отдельного `kgo_full`, latency или метрик масок.

### 5. Evaluation Data — данные оценки

Для каждого подхода указано **235** фотографий. Предполагается общая выборка сравнения; совпадение ID фото, независимость от train, class support, правила разметки и количество истинно отсутствующих площадок не предоставлены. Без них нельзя восстановить confusion matrix или надёжно оценить перенос на новые площадки.

### 6. Training Data — обучение

Система целиком не обучается end-to-end: YOLO, классификаторы и сегментаторы обучаются отдельно, затем соединяются правилами. Сведения по компонентам приведены в MC-01–MC-06. Соответствие предоставленной таблицы конкретным версиям training-данных неизвестно.

### 7. Quantitative Analyses — результаты

### 8. Ethical Considerations — этические аспекты

Ошибка оценки может вызвать задержку вывоза или лишний выезд. Ручная проверка нужна для ответов без метки и сомнительных фото; автоматическая модель не подтверждает факт выполнения работ. Не использовать эти метрики для оценки конкретных сотрудников. Ограничивать персональные данные в обучающих фото и сохранять происхождение разметки.

### 9. Caveats and Recommendations — ограничения

235 фото — ограниченная оценка без опубликованного состава и доверительных интервалов. Пайплайновые метрики не заменяют mAP детектора, IoU/Dice сегментаторов и метрики отдельных EfficientNet. Для нового выпуска предлагается **отсутствие ухудшения относительно действующей версии на той же независимой выборке** по macro F1, recall `kgo_full`, доле `No Zone` и ошибкам, с заранее согласованными допусками и проверкой срезов. Это предлагаемое правило приёмки, а не утверждённый численный SLA; baseline нужно пересчитать вместе с кандидатом. Значение `0.9534` из снимка нельзя превращать в универсальный порог для другого датасета или всех моделей.
