# Требования к итоговому проекту

Основано на файле `proj.pdf`.

## Обязательные требования

1. Исходные коды проекта должны находиться в репозитории GitHub.
2. В проекте должна использоваться предварительно обученная модель или LLM.
3. Проект оркестрируется с помощью CI/CD на Jenkins или GitLab.
4. Датасеты версионируются с помощью DVC и синхронизируются с удаленным хранилищем.
5. Разработка возможностей приложения, наборов фичей и версий данных проводится в отдельных ветках.
6. В конвейере запускаются unit tests и тесты качества данных.
7. Итоговое приложение реализуется в виде Docker image, сборка image происходит в конвейере.
8. При слиянии ветки в основной репозиторий должно выполняться Code Review.
9. Код приложения должен соответствовать стилю PEP8.
10. Приложение должно содержать тесты.
11. Docker image публикуется в Docker Hub.
12. В репозитории должна быть оформлена документация приложения.

## Как проект закрывает требования

- Web/API приложение реализовано на FastAPI в `fastapi_app`.
- Предобученные `.pt` и `.pth` веса используются приложением; доступные локально веса версионируются через `model_weights.dvc`, fallback-загрузка сохранена из `likip3/AI-Models`.
- Датасеты версионируются через `datasets.dvc`, DVC remote настроен на `s3://project-urfu-2026-dvc`.
- Основной CI/CD-конвейер настроен в `Jenkinsfile`.
- Unit tests находятся в `tests`; data quality tests находятся в `tests/test_data_quality.py`.
- PEP8/runtime-проверка выполняется через `ruff`.
- Docker image собирается из `Dockerfile`.
- Docker image собирается и публикуется в Jenkins; `.github/workflows/ci.yml` сохранен как дополнительная GitHub-проверка.
- Инструкции по запуску, Docker, DVC, Jenkins и модельным весам описаны в `README.md` и `docs/MLOPS.md`.
- Обучение моделей в конвейере не запускается: training-скрипты оставлены как исследовательская часть проекта.
